# Building UI with Vectra 2.0.0-alpha.0

Vectra is plain HTML: v-* classes for the look, native attributes and ARIA for state, data-v-* attributes for behaviour. Every component, class, hook, keyboard pattern and a valid example is in [reference.md](reference.md). Read the entry for each component before writing it. Generated by build/manifest.mjs; do not edit by hand.

## Setup

Install: `npm install @creativeigniter/vectra`, or copy dist/ from the release zip.

```html
<link rel="stylesheet" href="/vectra/vectra.css">
<script src="/vectra/vectra.js" defer></script>
```

- Copy dist/ to your site (here served at /vectra/), or import from node_modules/@creativeigniter/vectra/dist/.
- dist/vectra.css holds every direction; for production load dist/vectra.core.css, dist/vectra.components.css and one file from dist/directions/.
- Keep dist/fonts/ next to the CSS. Inter is only downloaded when a page uses it.
- As an ES module: import { toast, theme } from "@creativeigniter/vectra/dist/vectra.esm.js". It starts the hooks on import, like the script tag.
- Markup works without JS: dialogs, popovers, accordions and forms are native. Only tabs, toasts, menu arrow keys and the customizer need the script.

A page skeleton to start from:

```html
<!DOCTYPE html>
<html lang="en" data-direction="tech">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Page title</title>
  <link rel="stylesheet" href="/vectra/vectra.css">
  <script src="/vectra/vectra.js" defer></script>
</head>
<body>
  <a class="v-skip-link" href="#main">Skip to content</a>
  <header class="v-container">
    <nav aria-label="Main">...</nav>
  </header>
  <main id="main" class="v-skip-target v-container v-stack" tabindex="-1">
    <h1>Page title</h1>
    <p>Content.</p>
  </main>
  <footer class="v-container">...</footer>
</body>
</html>
```

## Rules (always)

- Load dist/vectra.css in the <head> and dist/vectra.js with defer. Keep dist/fonts/ next to the CSS and serve dist/icons/sprite.svg. Nothing else is needed: no CDN, no framework, no build step.
- Put lang and data-direction (tech, editorial, soft or glass) on <html>. Leave data-theme off to follow the OS; set data-theme="light" or "dark" only to force one.
- Use only classes listed in the Vectra reference (this file, the manifest or reference.md). Every Vectra class starts with v-. Never invent a class, and never use Bootstrap or Tailwind names (btn, card, d-flex, mt-4).
- Combine a base class with its modifiers on the same element (class="v-btn v-btn-primary v-btn-sm"). A modifier never works without its base class. Parts (v-card-header, v-dialog-body) go inside their component.
- States come from native attributes and ARIA, never .is-* or .active classes: disabled, hidden, open, aria-selected, aria-current, aria-expanded, aria-pressed, aria-invalid, aria-busy.
- JS behaviour is switched on by data-v-* attributes only, never by styling classes. Vectra starts every hook on load and on content added later, so no init call is needed.
- Listen for Vectra events (v:change, v:open, v:close, v:theme) with addEventListener; they bubble and are namespaced with v:.
- Use the native element first: <button> for actions, <a href> for navigation, <dialog> for modals, the popover attribute for menus and popovers, <details> for disclosure, <table> for data.
- One h1 per page, headings in order without skipping levels, and landmarks: header, nav with an aria-label, one main, footer. Start the page with a skip link to the main element.
- Every interactive element has an accessible name: visible text, or aria-label on icon-only buttons. Ids are unique and every aria-controls, aria-labelledby and aria-describedby points at an existing id.
- Every form control has a visible <label for> (or wraps it). Put hints and errors in elements linked with aria-describedby, mark errors with aria-invalid="true", and never use a placeholder as the label.
- Icons are <svg class="v-icon" aria-hidden="true"><use href="/icons/sprite.svg#name"/></svg> with a name from the icon list. Change /icons/ to wherever dist/icons/sprite.svg is served. Decorative icons stay aria-hidden.
- Theme with --v-* custom properties on :root or a wrapper, or with Vectra.theme.set(), never by overriding component selectors or hard-coding colours. Never put text on --v-accent-2.

## How to build a page

1. Start from the page skeleton above. Pick a direction with data-direction (tech, editorial, soft, glass).
2. Lay it out with the layout primitives: .v-container for the column, .v-stack for vertical rhythm, .v-cluster for rows that wrap, .v-grid for cards, .v-sidebar for a side panel and content.
3. Find each component in reference.md, copy its example and change only the content, ids and modifiers. Keep every attribute the example uses (roles, aria-*, data-v-*, type).
4. Use states, not classes: disabled, aria-busy="true" for loading, aria-invalid="true" for errors, aria-current="page" for the current link, hidden for hidden panels.
5. Add behaviour with the data-v-* hook the component lists. Use the JS API (Vectra.toast, Vectra.theme.set, Vectra.fieldState) only from your own code.
6. Check: one h1, labels on every control, unique ids, every aria reference resolves, no class outside the reference.

## Common patterns

- Auth (sign in, sign up, recovery, two-factor, sessions, first run): a .v-auth layout (see the auth entry under Sections) with a .v-field per input, a .v-btn v-btn-primary v-btn-block submit, and an .v-error-summary above the form after a failed submit (or a .v-alert for one server error such as a wrong password). Plain text links need no class: base.css styles them. Pages: examples/auth/.
- Sections (hero, features, pricing, testimonials, logos, FAQ, call to action, footer): .v-hero, .v-section-head above each section with an h2, a .v-grid of .v-card or .v-pricing, .v-logos, .v-testimonial, .v-accordion for the FAQ, .v-cta, .v-footer. Pages: examples/sections/.
- App pages: .v-navbar or the .v-app shell (.v-app-sidebar holding a .v-sidenav, .v-app-main), .v-bottombar on phones, a .v-page-header, a .v-toolbar above tables, a .v-danger-zone for destructive settings.
- States: .v-empty for nothing yet, .v-skeleton while loading, .v-alert or .v-callout for errors and notices, .v-toast via Vectra.toast() for results, .v-connection for offline.

## Never

- Never use classes from Bootstrap, Tailwind or Vectra v1 (btn, card, row, col-*, d-flex, text-muted). See the reference for the v- equivalent.
- Never add .active, .is-open, .is-invalid, .show or .disabled: use the attribute.
- Never put data-v-* hooks on elements other than the ones the reference names, and never call init functions by hand.
- Never load a CDN, an icon font or a framework for Vectra. Never copy ex-* classes or #i-* sprite ids from the galleries.
- Never use a div or span as a button, a placeholder as a label, or colour alone to show meaning.
- Never hard-code colours or radii: use the --v-* tokens.
