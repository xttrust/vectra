Getting started

Vectra needs no build step and no framework. Link the files, set a direction, write HTML. The same markup works in a static page, a Blade view, a Vue component or a Livewire template.

Get the files

Release zip. Each GitHub release has a zip with dist/, the examples and the fonts. Copy dist/ into your public folder.

npm. The package is @creativeigniter/vectra and ships both dist/ and src/. It is published with v2.0; until then, build it from the repository with npm ci && npm run build.

npm install @creativeigniter/vectra
What is in dist
FileWhat it is
vectra.css, vectra.min.cssEverything: core, all four directions and every component.
vectra.core.cssReset, tokens, base type, layout and utilities.
directions/*.cssOne file per direction: tech, editorial, soft, glass.
vectra.components.css, components/*.cssAll components, or one file each.
vectra.jsThe script-tag build: core plus every module, as window.Vectra.
vectra.esm.jsThe ES module build for bundlers.
fonts/, icons/Inter (latin and latin-ext subsets) and the SVG sprite with its manifest.

Plain HTML

The quickest start is the full bundle. Keep fonts/ next to the CSS file, since the CSS points at it with a relative path.

<!DOCTYPE html>
<html lang="en" data-direction="tech">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="/vectra/vectra.min.css">
  <script src="/vectra/vectra.js" defer></script>
</head>
<body>
  <main class="v-container v-stack">
    <h1>Hello</h1>
    <button class="v-btn v-btn-primary" type="button">It works</button>
  </main>
</body>
</html>

In production, load the core, one direction and only the components you use. Each file is small enough that a handful of links costs less than one large bundle.

<link rel="stylesheet" href="/vectra/vectra.core.min.css">
<link rel="stylesheet" href="/vectra/directions/editorial.min.css">
<link rel="stylesheet" href="/vectra/components/button.min.css">
<link rel="stylesheet" href="/vectra/components/card.min.css">

Direction, theme and no flash

data-direction picks the design direction; data-theme="light" or "dark" forces a theme, and leaving it out follows the OS live. If people can switch, Vectra.theme.set() saves the choice in localStorage. Put this small script in the <head>, before the CSS, so a saved choice applies before the first paint:

<script>
  (function () {
    var root = document.documentElement;
    try {
      var d = localStorage.getItem('vectra-direction');
      var t = localStorage.getItem('vectra-theme');
      if (['tech', 'editorial', 'soft', 'glass'].indexOf(d) > -1) root.dataset.direction = d;
      if (t === 'light' || t === 'dark') root.dataset.theme = t;
    } catch (e) {}
  })();
</script>

Laravel Blade

Copy dist/ to public/vectra/ (or publish it from node_modules in your deploy script) and link it from the layout. Blade output is plain HTML, so every class and data-v-* hook works as written.

<html lang="{{ str_replace('_', '-', app()->getLocale()) }}" data-direction="soft">
<head>
  <link rel="stylesheet" href="{{ asset('vectra/vectra.min.css') }}">
  <script src="{{ asset('vectra/vectra.js') }}" defer></script>
</head>
<body>
  @if (session('status'))
    <div class="v-alert v-alert-success" role="status"><p class="v-alert-body">{{ session('status') }}</p></div>
  @endif
  @yield('content')
</body>
</html>

Server-side validation errors map straight onto the field markup: aria-invalid="true" on the control and the message linked with aria-describedby.

<div class="v-field">
  <label class="v-label" for="email">Email</label>
  <input class="v-input" id="email" name="email" type="email" value="{{ old('email') }}"
    @error('email') aria-invalid="true" aria-describedby="email-error" @enderror>
  @error('email')<p class="v-field-error" id="email-error">{{ $message }}</p>@enderror
</div>

Vue and Inertia

With Vite, import the CSS once and the ES module build for the API. Templates use the same classes. There are no wrapper components to learn: a Vectra button in Vue is a <button class="v-btn">.

import '@creativeigniter/vectra/dist/vectra.css';
import { toast, theme } from '@creativeigniter/vectra/dist/vectra.esm.js';

// Anywhere in the app:
toast('Settings saved', { tone: 'success' });
theme.set({ direction: 'glass', mode: 'dark' });
<template>
  <form class="v-form" data-v-validate @submit.prevent="send">
    <div class="v-field">
      <label class="v-label" for="invite-email">Email</label>
      <input class="v-input" id="invite-email" v-model="email" type="email" required>
    </div>
    <button class="v-btn v-btn-primary" :aria-busy="sending" :disabled="sending">Send invite</button>
  </form>
</template>

Livewire, htmx and other late content

The Vectra core watches the page with a MutationObserver. Any element with a data-v-* hook that Livewire morphs in, htmx swaps in, or Vue mounts later starts on its own, and stops cleanly when it is removed. There is nothing to call after a swap.

  • Livewire. Hooks survive morphing. Keep wire:key on repeated items so an element and its module stay paired.
  • htmx. Swapped fragments initialise themselves; no htmx:afterSwap handler is needed.
  • By hand. Vectra.init(element) starts every hook inside an element straight away, and is safe to call more than once.

Icons and fonts

Icons are an SVG sprite: <svg class="v-icon" aria-hidden="true"><use href="/icons/sprite.svg#search"/></svg>. They inherit the text colour and size. To ship only the icons a site uses, run npx vectra-icons "pages/*.html" --out icons.svg. See Icons for the full set.

Inter is self-hosted with font-display: swap. A browser only downloads a font a page uses, so if you set your own --v-font-sans, Inter is never fetched.
