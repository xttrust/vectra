Contrast is built into the colour maths rather than checked afterwards. Pick any accent hue and text, borders and focus rings still pass AA.

OKLCH, fixed lightness

Every colour is written in OKLCH, where lightness is perceptual. Each direction fixes the lightness and chroma of its accent per theme and exposes only the hue, --v-accent-h. Changing the hue keeps the lightness, and with it the contrast against the page.

--v-accent: light-dark(
  oklch(calc(0.52 - 0.05 * var(--v-accent-dim)) 0.16 var(--v-accent-h)),
  oklch(74% 0.14 var(--v-accent-h))
);

The hue correction

Green and cyan read brighter than other hues at the same OKLCH lightness, so a lightness that passes for blue can fail for teal in a light theme. --v-accent-dim peaks for that band, and each direction subtracts a little light-theme lightness with it:

--v-accent-dim: max(0, cos((var(--v-accent-h) - 180) * 1deg));

Light and dark

Tokens use light-dark(), so one declaration holds both themes. Without data-theme on <html> the OS decides, live; data-theme="light" or "dark" forces one by setting color-scheme.

What is checked

  • Token sweep. tests/tokens.spec.js resolves every token in 4 directions, 2 themes and 13 hues and checks about 4,900 pairings: text at 4.5:1, control borders and the focus ring at 3:1.
  • Rendered contrast. On the gallery pages each text element is checked against what is actually painted behind it, including glass and gradients.
  • axe. Every gallery and this site run axe in every direction and theme.

Status colours (--v-success, --v-warning, --v-danger, --v-info) are shared by every direction and tuned the same way. Meaning never rests on colour alone: alerts have titles, badges have words, selected tags gain a check mark.
